	The Pebble Virtual Machine is the first attempt at an implementation of the Expressive Instruction
	set Computing model (EISC). Pebble should be considered the canonical or reference implementation
	of the EISC computing model and what a good demonstration of an ISA designed around the EISC
	computing model should look like.

	The EISC architecture is designed around one simple principle; an instruction should be able to be
	both flexible while providing a meaningful quantity of work. What was deemed the best way to achieve
	this was by creating incredibly generic and flexible instructions representing higher-level language
	concepts which then use addressing mode modifier statements to determine sub-operations they are to
	perform on the data given in the instruction operands, fused into one atomic operation. This model
	of computing would have a few dozen or less instructions total, each able to perform one incredibly
	rich operation, which can be fused with other operations keyword modifiers. This model of computing
	offers many advantages from an implementation and language perspective, including but not limited to
	vastly simpler compilers which do not have to break higher-level code into load/store or lower-level
	concepts, the ability for Just In Time or Dynamic compilers to better reason about complex structures
	like data and instruction relationships, and a major simplification for developers writing backed
	infrastructure against an EISC model of computer.

	A basic example of what an EISC instruction may look like could be the following

		STORE 0, 0, 1, 8, 3, 1

	This may look odd coming from more traditional load/store architectures. I mean come on, a six
	operand store?? woah, crazy, I know!

	In this example EISC ISA, the STORE instruction accepts four main operands. Operand one being the source
	data and operand three being the destination address, while two and four represent the addressing
	modifiers of operands one and three. In this example, say addressing mode 0 represents the concept
	of a literal reference, and addressing mode 8 represents a fused addition statement plus another addressing
	operand after it to fuse with the first, in this case being 1, which may represent an indirection
	statement.

	In this case, the operation would be the logical equivalent of 'store the literal zero to the logical
	address 8 + 3'. Now, this is a lot of information to be carried by one instruction. The interesting
	part, however, is that this is not a special store-literal-to-fused-addition-pointer instruction. It is
	just a generic data storing primitive instruction using fused addressing modifier statements. This also
	allows entire programs to be collapsed into single instructions. This same program in a one-operand
	RISC-style ISA could look something more like

		LOADI 8  /* load immediate 8 into the working register */
		ADD 3    /* add 3 to the working register */
		LOADADDR /* load the working register into the address register */
		LOADI 0  /* load immediate 0 into the working register */
		STORE    /* store the data in the working register (0) to the reference held in the address
			  * register (11) */

	five instructions that took, five very special purpose instructions, mind you. Something like this does
	not preserve data relationships very well; the compiler cannot easily know that the 8 and 3 are related
	immediately, or the fact that they will be used as an address later without complex look-ahead logic.

	Pebble refers to both the Pebble Virtual Machine and the Pebble ISA. Pebble is the canonical reference
	on what a proper EISC ISA would look like, and this is what this document shall describe; The Pebble ISA
	and concepts used in the Pebble Virtual Machine. Please keep in mind Pebble was designed from a software
	perspective, and in hence implemented as a language interpreter. (this language being the Pebble ISA)

	Pebble was designed primarily to be implemented in software. Pebble does not inherent the constraints
	most ISAs do, since it is not intended to be simple to execute in hardware directly. But this begs
	the question; Most ISAs are not executed in hardware directly, so why do they accept the same
	constraints that traditional ISAs do? Pebble explores a model where the freedoms software has are
	available inside of the ISA in itself directly and to explore what a model where software flexibility
	as a default may look like.

	Pebble is not a stack machine, nor is it a register machine. Pebble acts internally on named values
	which are dynamically typed and variable in size. In Pebble, there are only seven instructions. These
	include New, Func, End, Return, Call, If, and Escape. Each of these instructions accept addressing mode
	modifiers to modify how they may view their two operands, and each instruction can interpret each
	addressing mode in whatever way they deem best fit. This is one of the major powers of Pebble; A very
	simple ISA with incredibly expressive instructions.

	The addressing modifiers that exist include the Literal (") modifier, the True Literal (') modifier,
	the Forced Evaluation ({ / }) modifier, the Pointer (< / >), and the Bare ( ) modifier. These modifiers
	all represent instruction-dependent ways to modify a source operand before it is to be interpreted, and
	the meanings of them may vary per instruction. The general rule is that the Literal modifier represents
	an expression, the True Literal modifier represents a piece of data, the Forced Evaluation modifier 
	represents a pointer to an expression, the Pointer modifier represents a generic pointer, and the Bare
	modifier being completely instruction-dependent.

	The Pebble expression format follows the value, followed by a space, followed by the operator, followed
	by another space, followed by another value. In these schematics, the operator is stated to 'own' each
	space next to it, and one space is allowed to be shared by one or more operators. The valid operators
	include the Numeric Addition (+) statement, the Numeric Subtraction (-) statement, the Numeric
	Multiplication (*) statement, the Numeric Division (/) statement, the Numeric Greater than (>) statement,
	the Numeric Less than (<) statement, the Numeric Equal to (==) statement, the Numeric Not Equal to (!=)
	statement, the Numeric Greater than or Equal to (>=) statement, the Numeric Less than or Equal to (<=) 
	statement, the Sting Equal to (?=) statement, the String Contains (-?=) statement, the String Starts with 
	(s?=) statement, the String Ends with (e?=) statement, and the String Concat (s++) statement. Values can
	be anything that is a valid English character. The special cases include a value starting with the negative
	(-) sign, marking that the value is to be negative, or the forced precedence (( / )) sign, marking to
	'solve' the operation inside of that first and ignore the standard operator precedence. The standard
	operator precedence is ranked from tiers zero starting, with this tier being solved first. Tier 
	zero include Numeric Division and Numeric Multiplication. Tier one includes Numeric Addition and Numeric
	Subtraction. Tier two includes Numeric Less than, Numeric Greater than, Numeric Equal to, Numeric Not
	Equal to, Numeric Less than or Equal to, and Numeric Greater than or Equal to. Tier three includes 
	String Concat. Tier four includes String Starts with, String Ends with, String contains, and String
	equals. This ordering is checked first, and if two operators in the same tier cannot be ordered, then
	left to right associativity is to be assumed.

	The Numeric Addition operation will add the two numeric values presented and return the result of the
	addition. 
	The Numeric Subtraction operation will subtract the right numeric value from the left numeric value and
	return the result of the operation.
	The Numeric Division operation will divide the right numeric value from the left numeric value and return
	the result of the operation.
	The Numeric Multiplication operation will multiply the left numeric value from the right numeric value and
	return the result of the operation.
	The Numeric Equal to operation will check if the left numeric value is equal to the right numeric value 
	and return zero (0) if true and one (1) if false.
	The Numeric Not equal to operation will check if the left numeric value is not equal to the right numeric
	value and return zero if true and one if false.
	The Numeric Less than operator will compare the left numeric value to the right numeric value and return
	zero if the left numeric value is less than the right numeric value and one if it is not.
	The Numeric Greater than operator will compare the left numeric value to the right numeric value and
	return zero if the left numeric value is greater than the right numeric value and one if it is not.
	The Numeric Greater than or Equal to operator will compare the left numeric operator to the right numeric
	operator and return zero if the left numeric operator is greater than or equal to the right numeric
	operator and one if false.
	The Numeric Less than or Equal to operator will compare the left numeric operator to the right numeric 
	operator and return zero if the left numeric operator is less than or equal to the right numeric operator
	and one if false.
	The String Concat operator will take the two substrings specified and merge them into one string, returning
	the new string resulting from the two merged strings
	The String Contains operator will search the provided string specified by the second argument for the
	substring specified by the first argument and return 0 if the substring is found and 1 if it is not found.
	The String Equal to operator will compare two strings and return 0 if they match and 1 if they differ.
	The String Starts with operator will see if the first N chars, N being the length of the substring
	specified by the second argument, of the string specified by the first operator contains the substring
	specified by the second argument, and return 0 if said substring was found and 1 if it was not.
	The String Ends with operator will see if the last N chars, N being the length of the substring
	specified by the second argument, of the string specified by the first operator contains the substring
	specified by the second argument, and return 0 if said substring was found and 1 if it was not.

	If the line starts with the hash (#) or forward slash (/) characters, then the line is not to be
	interpreted as an instruction. If the instruction has more arguments than what is expected, they
	should be silently ignored. This is done to allow comments at the end of a line. There may not be
	a space or tab at the start of a line. A newline character at the start of a line is treated in the
	same way as a comment.

	The New opcode is a representation of a generic data manipulation primitive. This instruction accepts
	two operands, first being the destination to store to, and the second being the data to store to the
	destination. The destination operand uses the Literal modifier to represent the named variable to store
	the data to, the pointer modifier as a reference, which will be followed, to the named variable to store
	to, the True Literal modifier as an expression who's result is the name of the variable to store to, the
	Forced Evaluation modifier as representing a pointer to an expression, which will be followed, WHO's
	result is the name of the named variable to store to, and the Bare modifier in the same way as the True
	Literal modifier. The source operand treats the Bare modifier as marking the referenced variable name's
	data to be copied to the destination variable, the True Literal modifier as a piece of literal data to
	store to the destination, the Literal modifier to be an expression WHO's result is the data to store to
	the destination, the Forced Evaluation modifier as a pointer to an expression, which will be followed, 
	and to store the result of said expression to the destination, and the Pointer modifier as to store a 
	reference to the named variable to the destination.

	A few examples of this opcode in practice include

		New foo '1' / The variable foo is equal to the literal data 1
		New bar foo / The variable bar is equal to a copy of the current data in the variable foo, aka 1
		New baz <foo> / The variable baz contains a pointer to the variable foo
		New qux "1 + 2" / The variable qux contains the result of the expression 1 + 2, aka 3
		New quux '1 + 2' / The variable quux contains a representation of the expression 1 + 2
		New corge {quux} / The variable corge contains the result of the expression held in quux, aka 3
		New grault 'qux s++ corge' / The variable grault contains a representation of said expression
		New {grault} foo / The variable defined as the result of the expression held in grault, which
		/ resolves to '33', since qux contains the data 3 and corge contains the data 3 as well, resolved
		/ from the prior expression, to contain a copy of the data in foo, which is 1

	The Func opcode is the opcode to begin recording to the function table until the End opcode is reached. The
	Func opcode only takes one operand, being the name of the function to begin recording. This name can be a
	piece of literal text using the bare or True Literal addressing modes, the result of an expression via the
	Literal addressing mode, the result of an expression taken from a pointer with the Forced Evaluation
	addressing mode, or a pointer to a piece of text via the pointer addressing mode. Every opcode specified
	from the Func statement until the End statement will be recorded into the function entry under the defined]
	name. Multiple functions of the same name are allowed to be declared, in which case the last definition in
	terms of where it appears in the bytecode stream should be the one valid. However, functions should be
	recorded as they are seen, not at compile-time. This means a function cannot be called before it is defined,
	and if a function is re-defined but called before the re-definition, the old function value should be called.

	Some examples include

		Func a / start recording opcodes to function a
		New x '1' / an opcode in function a
		New y '2' / another opcode in function a
		End / end function a

		New x 'a s++ b' / create name template
		New a '1' / fill first value
		New b '2' / fill second value
		Func {x} / create function '12'
		New w '1' / an opcode in function 12
		End / end function 12

	Another opcode plays in hand with this, being the Call opcode, a call to a defined function. This opcode
	will call the function by name using a literal name via the bare and True Literal addressing modes, by
	the result of an expression from the Literal addressing mode, by the result of a pointer to an expression
	from the Forced Evaluation addressing mode, or by a pointer to the name by the Pointer addressing mode. This
	opcode only takes one operand, being the name of the function to cal.

	Some examples include

		New template 'base s++ modifier' / create name template
		New base 'func' / fill first value
		New modifier '0' / fill second value
		Call {template} / call the function func0

		Func a / define function a
		New x '1' / an opcode in function a
		End / end function a
		Call a / call function a; x now = 1
		Func a / re-define function a
		New x '2' / an opcode in the new function a
		End / end the new function a
		Call a / call the re-defined function; x now = 2

	The Return opcode can be used to return from a function early. This opcode takes no arguments and simply
	ends the function once it is hit inside of a function. This opcode is considered invalid when used outside
	of a function.

	Some examples include

		Func foo / define function foo
		Return / return from function foo
		New x '2' / this should never be hit
		End / end function foo
		New x '1' / set x to 1
		Call foo / x is still set to 1, since the code path changing it should never be hit

	A Return statement is said to be implicitly at the end of an End statement, but generally implementations
	do not literally inject that opcode in, but instead interpret them in a similar way. The End opcode ends
	the function definition and returns to the caller when hit, while Return only returns to the caller when
	hit, not ending the function yet.

	The If opcode is used for conditional control flow. This opcode is used to call a function if the stated
	expression resolves to zero. It accepts two arguments, the first being the name of the function to call,
	and the second being the expression to use. The first argument uses the bare addressing mode and True
	Literal to represent the function name directly, the Literal addressing mode to represent an expression
	who's result contains the function name, the Pointer addressing mode as a pointer to the function name,
	and the Forced Evaluation addressing mode as a pointer to an expression who's result should be the
	function name. The second operand uses the bare and True Literal addressing modes to represent the
	result, not of a expression, the Literal addressing mode to represent an expression to evaluate as the
	conditional, the Forced Evaluation mode as a pointer to an expression to be evaluated, and the Pointer
	addressing mode as a pointer to an expression to be evaluated, which is the same as the Forced Evaluation
	addressing mode.

	Some examples include

		Func a / define function a
		New x '1' / some instruction in function a
		End / end function a
		If a "1 > 0" / call function a if the expression == 0. This expression resolves to zero.
		
		New template 'base s++ modifier s++ modifier2' / define a template
		New base 'func' / define the first entry
		New modifier '0' / define the second entry
		New modifier2 '1' / define the third entry
		If {template} '0' / call function func01 if 0 == 0

		New expression '1 > 0' / define the expression to use 
		If a <expression> / evaluate the expression held in the variable and call the function a
				  / if it's result == 0
		If a {expression} / the same thing as above

	And finally, the Escape opcode, which is used to call a function using the Foreign Function interface.
	The FFI is used to implement the Pebble standard library, which will be described later. The FFI is
	a small interface to allow one programming language to use the Pebble internal variable table, hence
	allowing it to interface with Pebble code. The Pebble standard library uses an interface that is stable
	on the Pebble-facing side, but the FFI itself is implementation-specific. 

	The Escape opcode takes one argument, being the name of the FFI sequence to call. It accepts the
	addressing modes bare and True Literal as the name of the sequence to call, Literal as an expression
	who's result is the sequence to call, Pointer as a pointer to the name of the sequence to call, and Forced
	Evaluation as a pointer to an expression who's name is the sequence to call.

	FFI code is compiled into the virtual machine binary itself, not loaded at runtime, This means once a
	copy of the virtual machine is compiled, sequences cannot be added or removed. Sequences have access
	to only the internal variable table of the virtual machine, through whatever interface the implementation
	of the virtual machine and FFI wish to allow. Again, the Pebble-facing sequences of the Pebble standard
	library are stable, but the implementation of the FFI, it's interface and the FFI code itself is
	specific to the implementation of the virtual machine itself.
