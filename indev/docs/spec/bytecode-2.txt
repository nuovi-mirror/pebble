The Pebble Bytecode 2 Specification

This document acts as the single authoritative specification for the Pebble
programming language and Instruction Set Architecture, Version two. 
This document does not act as an introduction and will assume the reader
understands several concepts related to Pebble and general advanced
computing. For an introduction to Pebble, please read The Pebble 
Systems' Programmer's Handbook.

Expressions

	A valid expression is defined as a string sequence which contains
	at least two valid operators and at least one valid operation
	symbol. The ordering of this must follow the pattern of an
	operator, followed by a space, followed by an operation symbol,
	followed by a space, followed by another operator. This syntax
	can be thought of as the operator owning each space immediately next
	to it. One space is allowed to be owned by at most two operators
	at a time. This rule can be stacked arbitrarily, as long as the
	pattern described above still applies to the string in question
	created. When resolving an invalid expression, the parser should
	return the literal text given as an input for the expression
	without parsing it. An error should not be given, nor should the
	parser stop. A warning may be given if the implementation deems
	it fit.

Operators

	An operator is a piece of an expression representing data to
	perform an operation on via an operation symbol. Operators are
	classed in two ways; Stringly and numeric. Numeric operators may
	contain characters zero (0), one (1), two (2), three (3), four
	(4), five (5), six (6), seven (7), eight (8), or nine (9). A
	numeric operator may also optionally contain a minus sign (-)
	as the first character of the string. It may also contain a
	period (.) character as either any character besides the first
	character if there is no minus sign, or any character besides
	the first or second character if there is a minus sign. If a
	numeric value contains a leading zero, the value
	should be parsed as a Stringly value to preserve those, unless
	the value has only one leading zero followed by a period. In such
	a case, the value can be represented as a numeric value. This rule
	applies to the second character if the leading value is a minus
	sign. In such a case, the value can be parsed as numeric. A Stringly
	value is any string who contains only valid ASCII characters. A
	value should be determined if it is numeric before it is determined
	to be Stringly. Only one period and / or minus sign may be present
	in a numeric value. A numeric value must accurately represent
	values that can be represented by some platform-dependent sized
	value which is able to hold positive, negative, and floating-point
	numbers. Floating-point values are restricted to finite values.
	Three subclasses of numeric values are defined; signed, unsigned,
	and floating-point. A signed value must be able to contain some
	platform-dependent range of positive and negative numbers. An
	unsigned value must be able to contain some platform-dependent
	range of positive numbers. A floating-point value must be able
	to contain some platform-dependent range of finite floating-point
	numbers. Conversion rules of these sub-values are defined by the
	individual expressions which are performing the operation on the
	data in question. Values capable of holding unsigned values are
	to be defined as a 'word'. Values which are capable of holding
	signed values are to be defined as a 'signed word', or 'sword'
	for short. Values capable of holding floating-point values are
	to be defined as a 'float' or 'flt' for short. floating-point
	values are defined to only be able to represent finite numbers
	explicitly.

Conversion

	All numeric values are allowed to be converted into Stringly
	values. To convert a Stringly value into a numeric value, you
	must guarantee it can be represented as a valid numeric value,
	as described above. If it is not, the conversion will fail, and
	the converter is to decide how to handle such an error. 

	When converting numeric subclasses, it is important to note
	that no information should be lost. If the required conversion
	cannot be performed, a fatal error shall occur. Exact conversion
	rules are dependent on the machine and implementation, but every
	conversion which will not error must be safe; It must not overflow,
	underflow, or generate any other related hardware exception.

Operation symbols

	Operator symbols are character markers which represent an operation
	to be performed. An operator symbol may either act as Stringly, as
	in it accepts two string values and returns a string value, or
	numeric, as in it accepts two numeric values and returns a numeric
	value. If an operator's type within an expression does not match
	the type the operator symbol accepts, then implicit conversion
	should be performed if allowed. If conversion cannot be performed,
	then, in the case of converting a Stringly value to numeric, the
	Stringly value should be represented as the numeric value zero (0).
	Conversion of a numeric to a Stringly value should never fail
	unless the reason it is failing is due to security.

Numeric Addition

	The Numeric Addition operation is marked by the plus (+) symbol and
	is used to represent the logical operation of adding two numeric
	values together. This operation will accept two numeric values
	of any subclass, add them together, and return the result of the
	operation. In the case two operators do not match in subclass, then
	the operator in question should be converted to the correct type
	appropriately. In the case where such operation is not possible or
	permitted, a fatal error shall be given. This operator shall be
	able to detect if the operation may underflow or overflow, and
	in such a case, a fatal error shall be given.

Numeric Subtraction

	The Numeric Subtraction operation is marked by the minus (-) symbol
	and is used to represent the logical operation of subtracting
	the right operator from the left operator. This operation accepts
	two numeric values of any subclass. In the case two operators do
	not match in subclass, the operator in question should be converted
	to the correct type appropriately. In the case where such operation
	is not possible or permitted, a fatal error shall be given. This
	operator shall be able to detect if the operation may underflow or
	overflow, and in such case, a fatal error shall be given.

Numeric Division

	The Numeric Division operation is marked by the forward slash (/)
	symbol and is used to represent the logical operation of dividing
	the right operator from the left operator. This operation accepts
	two numeric values of any subclass. In the case two operators do
	not match in subclass, the operator in question should be converted
	to the correct type appropriately. In the case where such operation
	is not possible or permitted, a fatal error shall be given. This
	operator shall be able to detect if the operation may underflow
	or overflow, and in such case, a fatal error shall be given. If
	any of the operators in the expression are zero (0 or 0.0), then
	the result should be zero. If the result produces a remainder, then
	the remainder should not be included. If both operator are
	floating-point, then a floating-point operation shall be performed,
	but the decimal shall not be represented in the result given.

Numeric multiplication

	The Numeric Multiplication operation is marked by the pound (*)
	symbol and is used to represent the logical operation of
	multiplying the left numeric operator and right numeric operator.
	In the case the two operators do not match in subclass, the
	operator in question should be converted to the correct type
	appropriately. In the case where such operation is not possible
	or permitted, a fatal error shall be given. This operator shall
	be able to detect if the operation may underflow or overflow, and in
	such case, a fatal error shall be given.

Opcode parsing

	The opcode is the first string of text immediately after a newline
	immediately before a space. The operands of the opcode are defined
	to be the space-separated strings after the opcode up until a
	newline character is present. If the line begins with a space ( ),
	a tab (Tab), a newline (Enter), a forward slash (/), or a hash (#),
	then the line is to be ignored. If an opcode contains more operands
	than which are valid, the extra operands are to be ignored. If any 
	opcode is invalid, the data within an operand does not match what 
	the opcode expects, or opcode-specific parsing rules are broken, 
	a fatal error is to be thrown. Invalid syntax in this form is not 
	to be ignored.

Opcodes

	Valid opcodes include New, Func, Call, End, If, Return, and Escape.
	The first character of an opcode must be capitalized, with the rest
	being lowercase. Opcodes New and If accept two operands. Opcodes
	Func, Call, and Escape accept one operand. Opcodes End and Return
	accept no operands.

Opcode New

	The New opcode accepts a first operand as the name of the variable
	to store as a stringly value and the second as the data to place
	inside of the variable in question. For the second operand, if the
	string is enclosed by the double quotation (") character, then
	the data is used to represent an expression that will be evaluated,
	rather than literal data. The result of the expression is to be
	stored. In the case the string is enclosed by the single quotation 
	(') character, then the data is to be treated as literal or
	unparsed. If there are any spaces inside of those, the space is
	not considered a break to a new operand, but as part of the data
	itself. If there is no marking, then the string is used to
	represent a variable by name who's data will be copied into the
	referenced variable by the first operand.

Opcode Func

	The Func opcode accepts one operand, being the name of the function
	to define. This should be stringly. This will begin defining a
	function until the End statement is specified, in which all the
	opcodes which are in-between the Fund and End opcodes are to be
	treated as the information associated with the function. If the
	function name already exists, then this is to override the existing
	definition. The function is only valid to be called until after
	the Func keyword appears with the function name. Until then,
	the function is unmapped and calling it is to throw a fatal error.
	The information associated with the function is not to be executed
	as instructions until the function is called. The valid opcodes
	that may be associated with a function are New, Call, If, Escape,
	and Return. A function is not permitted to be defined inside of
	another function, hence why Func and End are not permitted inside
	of a function. Function's opcodes are to be mapped logically
	line-by-line; Once the Func keyword is found, the function name
	is mapped to the first opcode of the function body. Every opcode
	after this point until End is to be logically appended into the
	function's definition until the End opcode. A function can be
	called before it is complete, but in doing so, the rest of the
	function body that has not been seen is not mapped. However, by
	pure chance, this does still execute the entire function, since
	the calling of the function shall check against the End opcode
	for each opcode after the function's entry point, and finish
	the calling if so. Hence, although the function is not fully
	defined, it can still be called with the entire definition of
	opcodes being executed.

Opcode End

	The End opcode accepts no operands. This opcode is used to end the
	definition of a function declared by the Func opcode. Once this
	opcode is hit, the function's data should be fully mapped, unless
	the function is being called before a full definition, as described
	above. A return to the caller is implicit at an End statement.
	Returning rules as defined by the Return opcode are to be
	applied to this implicit return. This opcode is only valid within
	the scope of a function. If this opcode is found without a function
	definition related to it, a fatal error is to be thrown.

Opcode Return

	The Return opcode accepts no operands. This opcode is used to
	return early from a function. When this opcode is hit, the
	caller of the function execution is currently inside of is to be
	left, and the caller is to be returned to. The returned address
	shall be the address of the opcode immediately after the statement
	inside of the caller that was used to call the function. This
	opcode is only valid inside of a function. If this opcode is seen
	outside of a function, then a fatal error shall be thrown.

Opcode Call

	The Call opcode accepts one operand, which is the name of the
	function to call. The function's name specified by this operand
	is used as the new point of execution. The current point of
	execution should be saved to a new location for the duration of
	the function, then the current location of execution should become
	the entry point of the function specified, defined as the first
	opcode after the Func opcode defining the function. At the end
	of the function, defined above, the caller should be returned
	to as described by End and Return. If the function requested does
	not exist, then a fatal error should be thrown.

Opcode IF

	The If opcode accepts two operands, which is the name of the
	function to call if the second operand's expression resolves to
	zero (0) numeric, and the second operand, being the expression
	in reference. The expression in the second opcode should be
	enclosed by the double quotation (") character, as with the
	New instruction. If the expression resolves to the numeric
	value zero (0), then the function requested by the first operand
	will be called, as described by the Call opcode. If the expression
	described by the second operand is invalid or does not resolve to
	the numeric value zero (0), then execution shall continue.

Opcode Escape

	The Escape opcode accepts one operand, being the name of the escape
	sequence to call. If the escape sequence in reference does not
	exist, a fatal error shall be thrown. Because Escape in itself is
	an opcode, the escape sequence being called remains on the
	instruction boundary and is treated as one instruction.

Calling native code

	An interface for native code should be supplied by the
	implementation. The interface for native code is defined fully by
	the implementation, as long as it contains a way for native code
	to read and write variables inside of the virtual machine. The
	code for a native implementation of a routine is defined as an
	escape sequence, or an escape for short, and is to be executed
	using the Escape instruction described above. Arguments shall
	be passed to native code from the perspective of the Pebble
	programmer via special variables. This is also the way return
	values are passed from native code to Pebble programs. These 
	variables are separated by naming convention, starting with the
	characters '__Escape_', followed immediately by the name of the
	escape sequence, followed by the characters '_ARG' for arguments
	or '_RET' for return values, and finally followed by either the
	argument number for arguments or the return number for returns.
	These numbers begin at zero and may go up to any arbitrary value
	as long as the platform allows it. Native code may store data
	surviving beyond the instruction boundary via this same interface,
	creating variables of the naming convention starting with 
	'__Escape_', followed immediately by the escape sequence name,
	followed immediately by the underscore (_) character, followed by
	any arbitrary ASCII string the escape sequence wishes to add, or
	they may use some other implementation-defined method.
