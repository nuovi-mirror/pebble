std.term.color.basic.back causes a segmentation fault under the New Rock code

	include stdlib

	fn main ( ) ret {
		ret = '0'
		call std.term.color.basic.back ( 'green' )
	}

using the relivant standard library code

	"fn std.term.color.basic.back ( color ) ret {\n"
	". New __Escape_std.term.color.basic.back_ARG0 <__Func_std.term.color.basic.back_color>\n"
	". Escape std.term.color.basic.back\n"
	"ret = color\n"
	"}\n"

reliably on OpenBSD 7.9 amd64. It is not known if this bug is present on other platforms
or not. 

The escape call appears to jump backwards a few instructions somehow, causing a stack
overflow internally in the VM call stack, which is not caught by the stack checking
code. The cause of this is not known.
